## Что такое deep-search

deep-search — это глубокое исследование заданной темы. Реализуется за счёт **оркестрации** системы агентов.

Агенты:

- проводят поиск литературы
- выделяют ключевые результаты каждой статьи
- составляют план обзора
- пишут структурированный обзор с указаниями источников

Координирует **главный агент** (Build). Он запускает субагентов через инструмент `subagent`.

---

## Как устроена команда в OpenCode 2

```
главный агент (Build)
   ├── researcher  — ищет источники, read-only
   ├── analyzer    — извлекает результаты
   ├── writer      — пишет обзор в reports/
   └── reviewer    — проверяет ссылки, read-only (из 4.7)
```

Важно: `@general` — исполнитель, а не координатор. Он **не может** запускать других субагентов; цепочку строит главный агент.

---

## Шесть вопросов архитектуры

1. Какие **артефакты** производит система? (обзор, таблица источников, проверка)
2. Какие **роли** нужны под эти артефакты?
3. Почему каждую роль нельзя слить с другой? (контекст, права, независимость)
4. Какие **права** у каждой роли? Кто только читает, кто пишет?
5. Кто **проверяет** и какими доказательствами?
6. Сколько это **стоит** и когда остановиться?

Если ответов нет — команда ещё не спроектирована.

Раздатка «Чек-лист: нужен ли субагент».

---

## Роли — из артефактов, не из литературы

Литература даёт **паттерны**: кто кого проверяет, как передают работу.

Но роли выводим из **своих артефактов**:

```
обзор → writer
список источников → researcher
таблица результатов → analyzer
проверка ссылок → reviewer
```

Копировать роли из чужой статьи — значит копировать чужие границы. Статьи описывают другие задачи.

## Как сконфигурировать свою команду агентов

Главный секрет: OpenCode можно попросить написать конфиг себе.

Мы просим агента создать **мультиагентную систему** для deep-search.

В OpenCode 2 субагенты описываются в `.opencode/agents/*.md`:

- `description` — когда вызывать
- `mode: subagent`
- `permission` — что можно и нельзя
- тело файла — системная инструкция

## arXiv

**arXiv.org** — сервис препринтов, там публикуются статьи по физике, математике, экономике и т.д.

На текущий момент arXiv — главный источник информации по машинному обучению, ИИ, агентам.

Доступ к arXiv есть через MCP-сервер. В OpenCode 2 он добавляется через `opencode mcp add` и попадает в `mcp.servers`.

---

## Мета-конфигурирование OpenCode

- Подключаем arXiv через MCP.
- Просим найти статьи по deep-search (или любой другой задаче).
- Просим OpenCode проанализировать ключевые идеи и выявить совместимые с OpenCode 2.
- Просим на основе этих идей сделать рабочую конфигурацию и протестировать её.
- Перезапускаем OpenCode и пользуемся.

---

## Промпт генерации конфигурации

```
На основе этих идей создай в проекте мультиагентную систему
для deep-search, совместимую с OpenCode 2.

1. Опиши субагентов в .opencode/agents/:
   researcher, analyzer, writer, reviewer.
2. Роли выведи из артефактов (обзор, таблица источников,
   таблица результатов, проверка), а не копируй из статей.
3. Формат каждого файла — V2:
   description, mode: subagent, permissions.
   Тело файла — системная инструкция.
4. Права:
   researcher — только чтение;
   writer — пишет только reports/;
   reviewer — только чтение.
5. Не используй V1-поля permission/prompt/tools/temperature
   и инструмент task. Субагентов вызывает subagent.
6. Покажи структуру файлов.
```

## Тест системы

```
Протестируй систему на тестовом вопросе:
«какие методы используются для action recognition по pose
keypoints и какие у них accuracy?».

Покажи, что субагенты отработали и обзор собрался с
источниками. Сохрани результат в reports/deepsearch_setup.md.
```

Проверьте: главный агент вызвал субагентов, а не сделал всё сам.

---

## Тест на известном вопросе

Возьмите вопрос, на который вы **уже знаете 2–3 ключевые статьи**.

```
Проверь систему на известном вопросе:
я уже знаю статьи A, B, C. Найди их и покажи,
какие ещё источники добавляет система.
```

Если система не нашла известные статьи — проблема в поиске или ролях, а не в «плохом обзоре».

Это тот же принцип, что синтетические данные в уроке 2.6: известный ответ — эталон.

## Цена и независимая проверка

- параллельные исследователи ускоряют, но увеличивают расход токенов;
- каждая передача теряет часть контекста;
- `reviewer` должен быть read-only и проверять **ссылки/DOI**, а не пересказ автора;
- если задача маленькая — один агент дешевле и надёжнее.

Не «агент сам проверил», а `@reviewer` + ручная выборочная проверка ссылок.

---

## Проверка результата

```
Открой reports/deepsearch_setup.md. Проверь:
1. Каждая ссылка реально существует?
2. Каждый тезис подтверждается источником?
Выведи таблицу: тезис → источник → подтверждено?
```

Как всегда — не верим на слово. Агент мог придумать правдоподобный источник.

## Итог урока

- Deep-search = оркестрация: главный агент + субагенты + несколько источников + синтез
- В OpenCode 2 субагенты описываются в `.opencode/agents/` с `permission`
- Роли выводятся из артефактов, а не копируются из литературы
- `@general` не запускает других субагентов; координатор — главный агент
- Проверка: known-question test + read-only reviewer + ручная сверка ссылок
- Агент пишет конфиг сам себе (приём каталога №3)
- Выход: обзор с пронумерованными источниками, каждый тезис со ссылкой
