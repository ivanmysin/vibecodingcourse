# Свои субагенты: роль, права, проверка

**Урок 4.7 · Модуль 4. Компоненты ИИ агента и их настройка**

15 минут

---

## Зачем свой субагент

В OpenCode 2 уже есть `@general` и `@explore`. Зачем ещё один?

- `@general` — универсальный исполнитель
- `@explore` — универсальный читатель
- **свой агент** — постоянная роль с постоянными правами и критерием

Пример: reviewer, который **всегда** только читает и **всегда** возвращает PASS/FAIL с доказательствами. Это не «умнее», это предсказуемее.

---

## Роль — это не персона

Плохо:

> «Ты — опытный рецензент журнала Nature».

Хорошо:

```
Результат: PASS/FAIL + замечания с файлом:строкой
Вход: SPEC.md, отчёт, артефакты
Права: read-only; edit: deny, shell: deny
Критерий: каждое замечание подкреплено источником
Остановка: 3 однотипные ошибки → эскалация
```

Персона задаёт стиль. Роль задаёт **результат, права и границу**.

---

## Файл агента в OpenCode 2

```
.opencode/agents/
└── reviewer.md
```

`description` — по нему главный агент понимает, когда звать.

`mode: subagent` — агент не станет главным.

---

## Что внутри reviewer.md

```md
---
description: Проверяет отчёты и код, не меняет файлы
mode: subagent
permission:
  edit: deny
  bash: deny
  task: deny
---

Ты — ревьюер, не автор. Не правь файлы.
```

Тело файла — системная инструкция.

---

## Права — это настоящая граница

| Поле | Что делает | Для reviewer |
|---|---|---|
| `edit` | запись, изменение, patch | `deny` |
| `bash` | команды в оболочке | `deny` для отчёта; `ask` для ревью кода |
| `task` | запуск других субагентов | `deny` |
| `read` | чтение файлов | разрешено по умолчанию |

Текст «не правь файлы» — просьба. `edit: deny` — запрет, который сработает, даже если модель попробует.

---

## Создаём reviewer

```
Создай субагента reviewer в .opencode/agents/reviewer.md.

Frontmatter:
description: Проверяет отчёты и код, не меняет файлы
mode: subagent
permission:
  edit: deny
  bash: deny
  task: deny

Тело:
Ты — ревьюер, не автор. Не правь файлы.
Вход: SPEC.md, отчёт, артефакты.
Проверь каждое число по источнику, каждую ссылку/DOI, каждый вывод.
Выход: PASS или FAIL + замечания с файлом:строкой или DOI.
Если не можешь проверить — пиши «не проверено», а не «верно».
```

---

## Что получилось

- файл `.opencode/agents/reviewer.md` в проекте;
- `description` — условие вызова;
- `mode: subagent` — агент не станет главным;
- `permission` — реальные границы;
- тело — инструкция, которую видит только reviewer;
- `AGENTS.md` проекта при этом тоже действует: свой промпт **дополняет**, а не отменяет правила.

## Запускаем проверку

```
@reviewer Проверь reports/run.md по SPEC.md.
Каждое число сверь с results/*.csv.
Каждую ссылку/DOI — открой и подтверди.
Верни PASS/FAIL и таблицу:
| Утверждение | Источник | Проверено? | Статус |
```

Reviewer читает файлы, возвращает PASS/FAIL и замечания.

Главный агент сохраняет ответ в `reports/review.md` — сам reviewer файлы не пишет.

Если отчёта нет — проверьте `README.md`; смысл тот же.

---

## Проверяем, что права работают

Попросите reviewer:

```
@reviewer Исправь найденные ошибки в reports/run.md.
```

Reviewer откажется: правка запрещена.

Почему: `edit: deny`. Модель не может обойти это текстом — инструмент не сработает.

Это и есть разница между «я попросил не трогать» и «я запретил трогать».

## Карточка роли

```
Роль: reviewer
Результат: PASS/FAIL + замечания с доказательствами
Вход: SPEC.md, отчёт, артефакты
Права: read-only; edit/shell/subagent deny
Критерий: каждое замечание с файлом:строкой/DOI;
           нет «кажется» и «вероятно»
Остановка: 3 однотипные ошибки → эскалация
Эскалация: координатору/человеку
```

Карточка заполняется **до** создания агента. Если не заполняется — роль ещё не придумана.

Раздатки «Карточка роли» и «Чек-лист: нужен ли субагент».

## Когда свой агент не нужен

Задайте 6 вопросов:

1. Какую проблему решает разделение?
2. Почему не хватает `@explore`/`@general`?
3. Какой артефакт возвращает агент?
4. Какие минимальные права ему нужны?
5. Как проверяется результат?
6. Что при ошибке или тайм-ауте?

Если ответов нет — используйте встроенного агента.

---

## Когда лучше не делегировать

- задача маленькая;
- работа сильно связана;
- все правят одни файлы;
- нужно видеть процесс, а не результат;
- команда нужна «для солидности».

Каждый субагент — отдельный контекст, токены и время. Передача теряет часть информации.

---

## Ограничения OpenCode 2

- глубина субагентов по умолчанию **1**: reviewer не может создать своего reviewer;
- `@general` не запускает других субагентов — координатор главный агент;
- проектные инструкции `AGENTS.md` действуют и на субагентов;
- `shell: deny` — для ревьюера отчёта; для ревьюера кода можно `shell: ask` с allowlist на `git diff`, `git log`, `pytest`.

---

## Итог урока

- Свой субагент — это **файл роли**, а не «персона».
- Роль = результат + вход + права + критерий + остановка.
- Права задаются в `permission`, а не в тексте.
- Reviewer по умолчанию read-only и возвращает PASS/FAIL с доказательствами.
- `AGENTS.md` действует и на субагентов.
- Если роль не нужна — не создавайте её.
