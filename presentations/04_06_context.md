# Управление контекстом

**Урок 4.6 · Модуль 4. Компоненты ИИ агента и их настройка**

15 минут

---

## Ограничение: контекстное окно

У каждой языковой модели есть **контекстное окно** —
ограниченный объём текста за одну сессию (100–200 тысяч слов).

Что попадает в контекст:

- системный промпт агента
- `AGENTS.md`
- история разговора
- файлы, которые OpenCode прочитал за сессию
- описания skills и инструментов
- вызовы инструментов

---

## Рабочий контекст меньше полного

> При заполнении контекста больше 70-80% качество ответов LLM падает

Когда контекст переполняется, агент:

- забывает правила из `AGENTS.md`
- галлюцинирует
- не помнит ранние сообщения

---

## Приёмы гигиены контекста

1. **Новая сессия для новой задачи** — самое простое и надёжное
2. **`/compact`** — сжать историю без потери смысла
3. **Файлы-конспекты** (`NOTES.md`, `work_log.md`) — сохранить важное между сессиями
4. **Ветвление сессий** - агент будет помнить только часть материнской сессии.

Главный принцип: история чата — временная, файлы — постоянные.

---

## Приём 1: новая сессия

Закончили обсуждать анализ → открыли новую сессию для графиков.

- Контекст чистый
- Подходит для несвязанных задач

Но: новая сессия не помнит прошлую.
Важные решения записывайте в файл **до** закрытия.

---

## Приём 2: команда /compact

Когда сессия длинная (20-50 сообщений) и агент «поплыл»:

```
/compact
```

Агент перепишет историю в краткое резюме и продолжит.
Смысл не теряется, объём сокращается.

Проверка после сжатия:

```
Что мы обсуждали в самом начале этого разговора?
```

---

## Приём 3: файлы-конспекты

```
Создай NOTES.md в корне проекта и запиши в него краткое
резюме решений из нашего разговора:

1. данные: 200 наблюдений, 3 группы;
2. методы: t-тест с поправкой Бонферрони + Манн-Уитни;
3. графики: box-plot (300 dpi, colorblind-friendly);
4. выводы: различия control vs treatment_A значимы.

Формат: дата сверху, потом пункты.
```

---

## Что писать в файлы-конспекты

- **Дата и тема** разговора
- **Принятые решения** — какие методы, данные, ограничения
- **Открытые вопросы** — что не успели, что делать дальше
- **Важные находки** — «pandas 2.3 изменил API в методе X»

Это ваш долговременный слой памяти.

---

## Главные принципы управления контекстом

1. Держим объем контекста в рабочем диапазоне.
2. Даем агенту всю нужную информацию. Стараемся избегать попадания лишней информации.
3. Избегаем противоречивых инструкций. То, что написано в системном промпте агента, не должно противоречить тому, что написано в skills.
4. Проектируем субагентов. У каждого субагента свой контекст; передаём паспорт задачи (раздатка), а не всю историю.

---

## Итог урока

Контекст сессии теряется, контекст проекта (`AGENTS.md`, `.opencode/skills/`, файлы) — нет.

Три приёма + паспорт задачи закрывают 90% случаев:
новая сессия, `/compact`, файлы-конспекты.

Помните: три кнопки — и они окупаются за первую неделю.
