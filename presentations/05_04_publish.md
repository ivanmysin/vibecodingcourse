# После написания кода: документация и публикация

**Урок 5.4 · Модуль 5. Реализация большого проекта**

15 минут

---

## Код написан — что дальше

Пайплайн работает. Теперь нужно сделать его:

- **воспроизводимым** — чтобы запустить заново без вас
- **понятным** — чтобы через год вы сами разобрались
- **опубликованным** — чтобы коллеги могли его найти

Четыре шага — и несколько бонусных идей для науки.

---

## Шаг 1. Скрипт автозапуска пайплайна

Попросите агента сделать скрипт, который запускает **весь пайплайн**
одной командой — от сырых данных до итогового отчёта.

Никто (включая вас через год) не должен помнить,
в каком порядке запускать десять скриптов.

---

## Шаг 2. Документация к коду

Попросите агента добавить к каждой функции **описание**:
что делает, что на входе, что на выходе.

Это не «ради красоты» — без этого через месяц непонятно,
какой скрипт что считает и почему.

---

## Шаг 3. Обновить файлы репозитория

Проверить и обновить всё, что лежит в корне проекта:

- `README.md` — описание, структура, как запустить, откуда данные
- `AGENTS.md` — правила и соглашения (актуальные ли)
- `opencode.jsonc` — настройки OpenCode 2: модель, `permission`, MCP (без секретов)
- `SPEC.md` — что в итоге реализовано, что изменилось по ходу
- `requirements.txt` — версии библиотек

---

## Шаг 4. Влить в main и выложить на GitHub

- Все изменения — в ветку `main` (экспериментальные ветки влиты или удалены)
- Запушить на GitHub
- Проверить глазами «коллеги»: что видит посторонний, открыв репозиторий

---

## Бонус: идеи для научного проекта

Что ещё стоит сделать после написания кода:

- **Проверка воспроизводимости с нуля** — удалить результаты,
  пересоздать окружение и запустить пайплайн заново (как в уроке 3.4)
- **Безопасность** — убедиться, что сырых клинических данных и секретов в репозитории нет
- **Отрицательные результаты и ограничения** — зафиксировать их честно в отчёте (это тоже результат)
- **Открытая публикация данных** — выложить сами данные на Zenodo/OSF,  получить DOI для цитирования
- **Написать статью в научный журнал** - описать эксперименты, результаты, и в статье дать все ссылки 

---

## Итог урока

После кода — четыре шага:

1. Скрипт автозапуска всего пайплайна
2. Документация к коду
3. Обновить README / AGENTS.md / SPEC / requirements.txt
4. Влить в main и выложить на GitHub

Плюс научные бонусы: воспроизводимость с нуля, безопасность,
честные ограничения, открытая публикация данных.
