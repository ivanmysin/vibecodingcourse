# Паспорт задачи для субагента

> Раздатка к урокам 4.6, 5.1 и 5.3. Передавайте задачу как артефакт, а не как «продолжение чата».

---

## Шаблон

```
Задача: <что нужно сделать>
Зачем: <какой результат нужен и для чего>
Вход: <файлы, таблицы, SPEC.md, ссылки>
Границы: <что читать, что писать, что не трогать>
Критерий приёмки: <проверяемые пункты «да/нет»>
Доказательства: <файл/команда/лог, которые нужно вернуть>
Остановка: <3 одинаковые ошибки; нет данных; метод не работает>
Открытые вопросы: <что уже известно и что неизвестно>
```

---

## Пример

```
Задача: проверить отчёт reports/run.md на соответствие SPEC.md.
Зачем: перед коммитом убедиться, что числа и выводы не выдуманы.
Вход: SPEC.md, reports/run.md, results/*.csv, figures/*.png.
Границы: только чтение; ничего не править.
Критерий приёмки:
- каждое число в отчёте найдено в results/*.csv;
- каждая ссылка/DOI открывается;
- каждый вывод следует из данных.
Доказательства: таблица «утверждение → источник → статус».
Остановка: 3 однотипные ошибки → вернуть список и остановиться.
Открытые вопросы: нет.
```

---

## Что не передавать

- всю историю чата;
- свои рассуждения «почему я уверен»;
- чужие догадки без пометки «гипотеза»;
- пароли, ключи и персональные данные.

---

## Связь с SPEC

В `SPEC.md` уже есть разделы «Границы», «Остановка» и «Доказательства готовности». Паспорт задачи — это короткая выжимка из SPEC для конкретного субагента.
