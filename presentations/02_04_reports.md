# Генерация отчётов в Markdown и LaTeX

**Урок 2.4 · Модуль 2. Базовые сценарии использования ИИ агента**

15 минут

---

## Отчёт = связный рассказ

Что хотели узнать → что сделали → что получилось → что это значит.

Графики и таблицы — иллюстрации, а не сам рассказ.

Пять разделов:

**цель → данные → методы → результаты → выводы**

---

## Что умеет агент в отчёте

- Собрать **красивую таблицу** (выровненные колонки, подписи)
- **Встроить рисунок** в нужное место
- Взять числа строго из `results/*.csv`, а не «из головы»
- Собрать версию и в Markdown, и в LaTeX

---

## Markdown vs LaTeX

| Markdown | LaTeX |
|----------|-------|
| лаборатория, GitHub, OSF | журнальная статья, supplementary |
| читается как текст | компилируется в PDF |
| коммитится в Git | автогенерация таблиц и графиков |

Один и тот же контент можно представить в обоих форматах через агента.

---

## Компиляция LaTeX через агента

LaTeX-документ (`.tex`) нужно **скомпилировать** в PDF.

Агент запускает компилятор сам — вы не пишете команды руками.

Минимальный документ — `\documentclass{article}`, секции, таблица,
рисунок через `\includegraphics`.

---

## Чтение логов ошибок

LaTeX часто падает при компиляции — и выдаёт **лог ошибок**.

Раньше учёный сидел и вручную разбирал эти логи.

Теперь:

> «Скомпилируй `reports/run.tex`. Если упадёт — прочитай лог ошибок
> и исправь документ сам.»

Агент читает лог, находит причину, чинит и перекомпилирует.

---

## Ещё пример: статья под требования журнала

Когда статья готова — журнал требует свой формат.

- Берём **шаблон** с сайта журнала (LaTeX-класс или style-файл)
- Свою статью — в `.docx` (или другом удобном формате)
- Просим агента **сверстать всё под требования журнала**

```
У меня есть статья в article.docx и шаблон журнала
(journal-template.tex с сайта журнала). Сверстай статью
по шаблону: перенеси текст, добавь таблицы и рисунки
в нужные места, приведи библиографию к формату журнала.
Скомпилируй в PDF и покажи результат.
```

Это приём каталога №9: требования журнала → привести оформление в соответствие.

---

## Запрос к агенту

```
Собери отчёт reports/run.md по нашим результатам (карты активации,
пространственная информация, перебор sigma). Пять разделов:
цель → данные → методы → результаты → выводы.

Включи:
- красивую таблицу со значениями пространственной информации
  по сессиям;
- встроенный рисунок с картой активации.

Числа бери только из results/*.csv, не выдумывай.

Затем сделай версию reports/run.tex с теми же разделами, одной
таблицей и одним рисунком.

Скомпилируй run.tex в PDF. Если компиляция падает — прочитай
лог ошибок и исправь документ, затем перекомпилируй.

Все подписи на русском.
```

---

## Главная проверка отчёта

После сборки — 30 секунд на сверку:

> «Сверь каждое число в отчёте с источником (`results/*.csv`)»

Это ловит 90% «фантазий» модели —
когда агент выдаёт правдоподобные, но выдуманные цифры.

## Итог урока

- Markdown — для лаборатории и GitHub
- LaTeX — для журнала и supplementary
- Компиляция и починка ошибок — тоже через агента

Один и тот же результат — в двух форматах, без единой строки руками.
