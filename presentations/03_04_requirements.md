## README.md — лицо проекта

Первое, что видит посетитель GitHub. Без README репозиторий выглядит брошенным.

Четыре раздела:

1. **Описание** — что за проект, на какой вопрос отвечает
2. **Структура** — что лежит в `data/`, `scripts/`, `figures/`, `reports/`
3. **Запуск** — как воспроизвести (создать `.venv/`, поставить библиотеки, запустить)
4. **Данные** — откуда данные, ограничения, лицензия

## LICENSE — правила игры

Без лицензии действует «все права защищены»: даже коллега
не может использовать ваш код без разрешения.

| Лицензия | Что разрешает |
|----------|---------------|
| **MIT** | делайте что хотите, лишь бы указали автора |
| **Apache 2.0** | то же + защита от патентных претензий |

Для учебных и научных проектов берём **MIT**.

## LICENSE через OpenCode

```
Создай файл LICENSE в корне проекта. Это должна быть короткая
MIT-лицензия на английском: Copyright (c) <текущий год> <имя
из git config user.name>. Полный стандартный текст MIT
(как на opensource.org/licenses/MIT).
Возьми имя автора и год из текущей конфигурации Git.
```

## Приватный vs публичный

| Приватный | Публичный |
|-----------|-----------|
| виден вам и приглашённым | виден всему миру |
| рабочие исследования, диссертации, черновики | опенсорс, обучающие материалы |
| безопасный дефолт | осознанное решение |

Изменить видимость: github.com → Settings → Danger Zone →
Change repository visibility (5 секунд).

## Git — не только для кода

Git версионирует любые текстовые файлы:

- **Заметки в Obsidian** — папка `.md`-файлов как репозиторий
- **Лабораторный журнал** — файл на каждый день, версионируется и бэкапится
- **Протоколы исследований** — каждое изменение протокола = коммит с пояснением

Это «машина версий для текстов» — спокойствие за свои записи.

## .gitignore: что и почему прячем

- **Окружение и кеш** (`.venv/`, `__pycache__/`) — воспроизводится из `requirements.txt`
- **Секреты** (`.env`, токены) — риск утечки
- **Большие данные** (`data/raw/*.csv`) — весят сотни мегабайт, Git их не любит
- **Служебное** (`.DS_Store`, `Thumbs.db`) — артефакты редакторов
- **Артефакты сборки** (`dist/`, `build/`) — воспроизводятся командой

## requirements.txt — паспорт окружения

Библиотеки обновляются: что работало на pandas 2.2, может сломаться на 3.0.

```
Создай файл requirements.txt в корне проекта. Внутри — полный
список всех библиотек, которые установлены в .venv/ в этом
проекте, с указанием точных версий (формат pandas==2.2.3).
Не включай pip, setuptools, wheel — только те библиотеки,
которые мы реально используем в scripts/.
Покажи содержимое файла.
```

Через два года на другом компьютере поднимется та же среда.

## Чек-лист перед коммитом (5 вопросов)

1. Закончен ли смысловой кусок?
2. Пойму ли я сообщение через месяц?
3. Если откатить — проект не сломается?
4. Нет ли в Changes файлов, которые не должны быть в репозитории
   (`.venv/`, `data/raw/*.csv`, `.env`)?
5. Если менялся запуск или данные — обновлён ли `README.md`?
