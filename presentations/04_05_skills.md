# Skills: переиспользуемые инструкции

**Урок 4.5 · Модуль 4. Компоненты ИИ агента и их настройка**

18 минут

---

## Что такое skill

Skill — это файл с инструкциями.

```
.opencode/skills/
└── run-stats/
    ├── SKILL.md               инструкция + метаданные
    ├── references/
    │   └── methodology.md     подробности
    └── assets/
        └── template.csv       шаблоны
```

Агент видит список навыков и **сам загружает** нужный, когда задача совпадает с описанием.

---

## Skill не вызывается как `/команда`

Это важное различие OpenCode 2:

| Механизм | Кто вызывает | Где лежит | Как проверить |
|---|---|---|---|
| **Skill** | агент, по описанию | `.opencode/skills/<id>/SKILL.md` | виден вызов `skill` в логе |
| **Command** | пользователь, `/name` | `.opencode/commands/<name>.md` | набрать `/name` |
| **Subagent** | агент или вы, `@name` | `.opencode/agents/<name>.md` | `@name` |
| **AGENTS.md** | всегда | корень проекта | новая сессия |

Если хотите именно `/run-stats` — это **команда**, а не skill. Обычно достаточно skill: агент сам поймёт, когда его применить.

---

## Анатомия SKILL.md — четыре части

1. **Фронтматтер** — метаданные YAML в начале файла (`name`, `description`)
2. **`description`** — не summary, а **условия срабатывания**:
   «применяй, когда пользователь даёт CSV и просит описательную статистику»
3. **Инструкция** — что делать (по шести частям из урока 4.1)
4. **Подводные камни** — типичные ошибки

В OpenCode 2 ID навыка берётся из пути: папка `run-stats` → skill `run-stats`. Поле `name` — отображаемое имя.

## Примеры skills для науки

1. **Справочники по библиотекам и API** 
2. **Проверка результата** — какие графики построить
3. **Получение и анализ данных** — считай из `data/raw/`, оставь колонки X, Y
4. **Автоматизация рутины** — «еженедельный отчёт по эксперименту»

## Прогрессивное раскрытие

Основной `SKILL.md` короткий (1 экран),
детали выносятся в `references/` и `assets/`.

Агент читает детали только когда они нужны — экономит контекст.

---

## Создаём skill run-stats

```
Создай skill с именем run-stats в папке .opencode/skills/.

Структура:
.opencode/skills/run-stats/
├── SKILL.md        — короткая инструкция (1 экран)
└── references/
    └── methodology.md  — подробная методология
```

---

## Фронтматтер SKILL.md

```
SKILL.md с фронтматтером:
---
name: run-stats
description: "Применяй, когда пользователь даёт путь к CSV
  и имя числовой колонки и просит посчитать описательную
  статистику по группам."
---
```

---

## Инструкция и references

```
После фронтматтера — инструкция:
Роль: биостатистик.
Цель: описательная статистика числовой колонки по группам.
Формат вывода: Markdown-таблица + CSV в results/.
Ограничения: Python, pandas. Комментарии на русском.
Критерии приёмки: все колонки на месте, N совпадает.
Gotchas:
- Не округляй статистики — пиши как есть.
- Если есть NaN — укажи n_missing явно.

references/methodology.md — длинная методология:
что такое SD и IQR, когда mean vs median, проверка
нормальности, работа с пропусками, функции pandas.

Создай обе части и покажи итоговую структуру.
```

## Проверяем: обычный запрос

```
Посчитай описательную статистику по rt_ms в
data/behavior_sample.csv по группам.
```

Агент должен сам загрузить `run-stats` — в логе будет виден вызов инструмента `skill`.

Если хотите загрузить навык вручную, упомяните его:

```
@run-stats Посчитай описательную статистику по rt_ms...
```

---

## Если нужна именно `/команда`

Создайте отдельный файл `.opencode/commands/run-stats.md`:

```md
---
description: Описательная статистика по CSV
agent: build
---

Посчитай описательную статистику по $ARGUMENTS.
```

Теперь `/run-stats data/behavior_sample.csv rt_ms` работает как команда, а skill остаётся знанием, которое агент подгружает.

---

## Советы из гайда Anthropic

1. **Не пишите очевидное** — модель многое знает; пишите подводные камни
2. **Собирайте типичные проблемы в отдельный раздел** — это самый ценный контент
3. **Не загоняйте агента в жёсткие рамки** — skill это подсказки, не скрипт
4. **`description` — для модели, не для человека** — формулируйте как «применяй, когда…»

## Итог урока

Skill — это переиспользуемая инструкция: создали раз, агент зовёт её сам.

Ключевые идеи:

- skill лежит в `.opencode/skills/<id>/SKILL.md`
- агент загружает его через инструмент `skill` по `description`
- `/команда` — отдельный механизм, не skill
- прогрессивное раскрытие через `references/`
- типичные проблемы — самое ценное
- skill ≠ `AGENTS.md`: `AGENTS.md` — «конституция проекта», skill — «процедура»
