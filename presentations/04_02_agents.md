# AGENTS.md — правила проекта

**Урок 4.2 · Модуль 4. Компоненты ИИ агента и их настройка**

15 минут

---

## Что такое AGENTS.md

`AGENTS.md` — файл-инструкция, который объясняет агенту,
как устроен ваш проект и по каким правилам в нём работать.

- Это **не документация для чтения**, а набор директив для выполнения
- Говорит с машиной на её языке: конкретные команды, ограничения, структура
- Агент читает его автоматически в начале каждой сессии

---

## AGENTS.md vs README.md

| README.md | AGENTS.md |
|-----------|-----------|
| для людей | для агента |
| что и зачем | как именно |
| меняется редко | меняется по мере роста проекта |
| описание, установка, лицензия | структура, стиль, ограничения, команды |

Оба лежат в корне проекта, но решают разные задачи.

---

## Где лежит AGENTS.md

- **В корне проекта** — правила, специфичные для проекта
  (работают, пока вы в этой папке)
- **Глобальный** `~/.config/opencode/AGENTS.md` — личные правила,
  действуют во всех сессиях (не коммитится в Git)
- **В подпапках** — более узкие правила; OpenCode 2 подхватывает их по мере работы

Для учебного проекта достаточно одного файла в корне `research_project/`.

В OpenCode 2 это единственный формат проектных инструкций: `CLAUDE.md` как fallback больше не используется.

---

## Кого касаются правила

`AGENTS.md` — это инструкции проекта, а не «промпт только для главного агента».

- главный агент читает его при старте сессии
- субагенты тоже получают проектные инструкции
- у своего субагента может быть **дополнительный** system prompt, но правила проекта продолжают действовать

Поэтому не стоит рассчитывать, что субагент «ничего не знает о проекте».

---

## Как его создать

Команда `/init`:

- OpenCode сканирует проект и генерирует базовый `AGENTS.md`
- Если файл уже есть — попытается дополнить

Или текстовый запрос: «создай AGENTS.md для моего проекта».

---

## Что писать: базовые разделы

Для научного Python-проекта обычно хватает:

1. **Описание проекта** — что за проект, на какой вопрос отвечает
2. **Структура директорий** — `data/raw/`, `scripts/`, `figures/`, `reports/`
3. **Стиль кода** — язык комментариев, библиотеки
4. **Графики** — размеры, dpi, палитра
5. **Команды** — как запускать скрипты
6. **Ограничения и запреты** — что не трогать

---

## Пример: научный проект

```
Открой AGENTS.md. Дополни его блоками (не переписывай):

## Описание проекта
- Анализ поведенческих и нейрофизиологических данных
  в академическом проекте. Отвечаю на русском.

## Структура
- data/raw/ — сырые данные, только чтение.
- scripts/ — скрипты с префиксом NN_.
- figures/ — графики (PNG 300 dpi + PDF).
- reports/ — отчёты.

## Стиль кода
- Комментарии на русском. Имена переменных — английский,
  snake_case. Библиотеки: pandas, numpy, matplotlib,
  seaborn, scipy, pingouin.
```

---

## Пример: научный проект (продолжение)

```
## Графики
- 8 см шириной, 300 dpi, colorblind-палитра,
  подписи осей на русском.

## Безопасность
- Не удалять файлы из data/raw/ без подтверждения.
- Не читать .env. Не трогать файлы вне scripts/ и figures/.
```

Важно: этот блок — **объяснение**, а не замок. Если нужно именно запретить запись, это делается в `permission` (урок 1.5).

---

## AGENTS.md — объяснение, не замок

`AGENTS.md` говорит агенту, что важно, и помогает не ошибаться.

Но если модель ошибётся или поддастся чужому тексту, правило в файле её **не остановит**.

Технические запреты живут в `permission`:

```jsonc
{
  "permission": {
    "edit": { "*": "allow", "data/raw/**": "deny" }
  }
}
```

Поэтому в `AGENTS.md` пишем «зачем», а в правах — «что нельзя».

Личность влияет на стиль и выбор методов, но не заменяет границы.

---

## Лучшие практики

1. **Пишите конкретно, не абстрактно**
   — не «запускай тесты», а точную команду; не «конфиг в корне», а путь
2. **Держите файл актуальным**
   — перестали использовать библиотеку → удалите упоминание
3. **Не перегружайте** — 1–2 экрана максимум;
   детали — в `docs/`, агенту говорим «прочитай»
4. **Разделяйте по зонам** — у каждого блока своя ответственность

---

## Чего НЕ класть в AGENTS.md

- **Секреты** (API-ключи, пароли) — они вводятся через `/connect` и хранятся в OpenCode, а не в проекте
- **Огромные куски документации** — это в `docs/`
- **Неактуальные правила** — только шум в контексте

---

## Проверка: правила применились

Новая сессия → вопрос **без указания роли**:

> «Какой тест выбрать для сравнения RT двух групп, если распределение
> скошено и есть выбросы?»

Если `AGENTS.md` заполнен — ответ придёт в нужном стиле
(биоинформатик, по-русски, с предложением посмотреть распределение).

Правила действуют с первой секунды — это не магия, а файл.
