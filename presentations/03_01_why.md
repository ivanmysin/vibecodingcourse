## Две типичные проблемы

**История 1.** Переписал скрипт, чтобы «немного улучшить».
Через два часа понял, что в другом месте проекта что-то важное сломалось. Придется долго искать причину проблемы, чтобы продолжить работу.

**История 2.** Ноутбук залил кофе и он не работает. Все локальные файлы потеряны: диссертация,
скрипты и данные.

Вывод: нужна копия в облаке.
Сегодня мы его заведём.

---

## Что такое контроль версий

Контроль версий — это система, которая хранит **историю изменений** проекта.

- Каждый коммит — «снимок» состояния всех файлов на этот момент
- Снимки выстраиваются в цепочку — можно вернуться к любому прошлому состоянию
- Всегда видно, что менялось и когда

Аналогия: «история правок» в Google Docs или Word,
но для **всего проекта сразу**.

---

## Снимки вместо копий файлов

Без контроля версий люди делают копии: `финальный_финальный_2.docx`.

С контролем версий — одна история, где каждый шаг помечен:

- что изменилось
- когда
- с каким пояснением (сообщение коммита)

Можно откатиться к любой версии и сравнить две версии между собой.

## Git и GitHub: в чём разница

| Git | GitHub |
|-----|--------|
| программа на вашем компьютере | сайт github.com |
| хранит историю изменений | облачное хранилище для репозитория |
| работает без интернета | требует регистрации и интернета |

Аналогия: Git — документ с записями эксперимента, где хранится не только текущее состояние, но вся история изменений.
GitHub — облачное хранилище, где лежит копия документа.

---

## Коммит и push — два шага

1. **Коммит** — записываете «снимок проекта» в локальный Git
2. **Push** — отправляете этот снимок в облако, на GitHub

Без push ваш репозиторий живёт только на одном компьютере.
С push — появляется запасная копия в облаке.

---

## Зачем заводить репозиторий: 4 причины

1. **Бэкап** — ноутбук сломался: `git clone` на новом — и всё на месте
2. **Несколько устройств** — дом, лаборатория, библиотека: один репозиторий
3. **Командная работа** — несколько человек правят один проект
4. **Шеринг** — ссылка коллеге или рецензенту вместо zip-архивов

## Gitnuro — графический интерфейс для Git

- Бесплатная, open source, без привязки к одному аккаунту
- Все операции — кнопками, без терминала
- Windows: `.exe` · macOS: `.dmg` · Linux: `.deb`/`.rpm`

В нашем курсе мы не вводим команды Git руками — только кнопки.

---

## Шаг 1. Создать репозиторий на github.com

1. Зайти на `github.com`, залогиниться
2. В правом верхнем углу: «+» → «New repository»
3. Имя: `research_project`
4. Видимость: **Private** (приватный — видите только вы и приглашённые)
5. **Не ставить** галочки «Add README», «Add .gitignore», «Choose license»
6. «Create repository» → скопировать URL вида
   `https://github.com/<ваш-логин>/research_project.git`

---

## Шаг 2. Подключить папку в Gitnuro

- **File → Open Repository** → выбрать папку проекта
- Если спрашивает «создать репозиторий?» — да

Затем привязка к облаку (remote):

- **Repository → Remotes → Add Remote**
- Имя: `origin` (стандартное имя главного удалённого репозитория)
- URL: вставить скопированный с github.com

---

## Шаг 3. Создать .gitignore

`.gitignore` говорит Git, какие файлы НЕ отправлять в репозиторий:

```
Создай файл .gitignore в корне проекта. Внутри должны быть
правила для типичного научного Python-проекта: .venv/,
__pycache__/, *.pyc, .env, *.csv в папке data/raw/,
.DS_Store, .ipynb_checkpoints/, *.egg-info/, dist/, build/.
Не трогай никакие другие файлы. Покажи содержимое после
создания.
```

---

## Шаг 4. Первый коммит

В Gitnuro на вкладке Local Changes — все файлы проекта,
но `.venv/`, `__pycache__/` и `data/raw/*.csv` исчезли (это правильно).

Сообщение коммита пишем так, будто через год объясняем сами себе:

> `начальная структура проекта: README, скрипты, figures`

Не «first», не «init», не «asdfg».

---

## Шаг 5. Push и проверка

- В Gitnuro нажать **Push** → через 3–5 секунд «Push successful»
- На github.com обновить страницу:
  - файлы проекта на месте
  - `.venv/`, `__pycache__/`, `data/raw/*.csv` — не видны (в игноре)
  - в истории — первый коммит

---

## Итог урока

Репозиторий в облаке, история зафиксирована, секреты и окружение не утекли.

Git — локальная история изменений.
GitHub — облачная копия этой истории.
Коммит — снимок. Push — отправка снимка в облако.
